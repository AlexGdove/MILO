# Принятые решения MILO

Журнал решений, которые **утвердил пользователь** (или которые следуют из его явных требований). Предложения без утверждения сюда не попадают — они в `docs/TASKS.md` («Открытые вопросы»). Новое решение добавляется в конец с датой; отменённое не удаляется, а помечается «Заменено решением №…».

Даты — 2026-11-04 (одна рабочая сессия), если не указано иное.

## Продукт и бренд

1. **Название — MILO** (Meal Intelligence & Lifestyle Organizer). Существующее приложение подсчёта калорий развивается как MILO, а не создаётся заново. Главное слово — MILO, расшифровка не обязательна везде.
2. **Концепция продукта**: шире подсчёта калорий — дневник, кладовая, рецепты, список покупок. Ключевая идея: пользователь видит, что есть дома; готовка по рецепту списывает продукты; закончившееся и недостающее можно добавить в покупки **или пропустить — по решению пользователя, без автодобавления**.
3. **Айдентика**: палитра концепции C «Орбита» + знак концепции A «Пропорция» (три столбика БЖУ, силуэт «M»). _Знак заменён решением №22; палитра и шрифты действуют._ Концепции: https://claude.ai/artifact/KPXspyqYRa6yFwPstU5i5M. Детали — `docs/brand.md`.
4. **Шрифты**: Onest (текст/UI) и Unbounded (логотип, крупные числа), подключение пакетами `@fontsource` (офлайн в PWA). Зависимость одобрена, ещё не установлена.
5. **Единицы в кладовой**: г, мл, шт (для шт — вес одной штуки); минимальный остаток на продукт.
6. **Рецепты**: сначала свои, локально; внешний API и общая база пользователей — позже, через общий интерфейс `RecipeSource`. Конкретный API не выбран.
7. **Дизайн-система** (из утверждённого плана): двухслойные токены в `frontend/src/app/styles/variables.css` (примитивы `--milo-*` + семантические `--color-*`, `--font-*`, `--space-*`, `--radius-*`, `--shadow-*`), светлая и тёмная тема (`prefers-color-scheme`, готовность к `[data-theme]` без UI-переключателя), литералы в CSS-модулях запрещены. Цвета БЖУ: белки — светлый ультрамарин, жиры — янтарь `#FFB84D`, углеводы — лаванда `#9B8CFF`; мята `#3CCB9A` — только подсказки.
8. **Навигация после шага «Список покупок»**: Сегодня · Дневник · Рецепты · Кладовая · Покупки; профиль — из шапки. _Состав вкладок заменён решением №24._ Раздел «Продукты» переименовывается в «Кладовая» (`/pantry`, редирект со `/products`).

## Архитектура и стек

9. **Монорепо npm workspaces**: `frontend/` (React PWA), `backend/`, `mobile/`. Backend и mobile — заготовки; их стек **не выбран** (пользователь выбрал «пока только заготовка»).
10. **Фронтенд**: Vite 8, React 18, TypeScript 5.9 (зафиксирован `~5.9`: TS 7 мог не поддерживаться typescript-eslint), react-router-dom 7, Zustand 5, CSS Modules, vite-plugin-pwa 2. Без UI-библиотек.
11. **FSD** (`app → pages → widgets → features → entities → shared`), импорт слайсов только через `index.ts`, алиас `@/`. Контроль — ESLint 9 flat config + `eslint-plugin-boundaries` + `no-restricted-imports`; порядок импортов — `eslint-plugin-import-x`; Prettier.
12. **Хранение данных**: локально, Zustand `persist` только через `shared/lib/storage` (`persistStorage`, `storageKey`). Префикс ключей `milo:`; данные со старого префикса `calorie-tracker:` переносятся при первом чтении.
13. **Изменение формы сохранённых данных** — только с повышением `version` и функцией `migrate` + тестом (иначе Zustand отбрасывает данные пользователя; подтверждено тестом 2026-11-04).
14. **Тесты**: Vitest + React Testing Library (не Jest), jsdom.
15. **Серверное состояние** (когда появится бэкенд/API) — TanStack Query; большие списки — TanStack Virtual. **Сейчас не установлены**, добавление требует отдельного одобрения. Redux не использовать.
16. **Одобренные зависимости из плана**: `@fontsource/onest`, `@fontsource/unbounded` (ещё не установлены); `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/dom`, `@testing-library/jest-dom`, `@testing-library/user-event` (установлены). Другие — только с одобрения.

## Процесс

17. **Git** (раздел 11 требований): `main` — стабильная, `dev` — интеграция; задачи — в рабочих ветках от `dev`. Коммиты, merge в `dev`, push, операции с ветками вне схемы — только с явного разрешения пользователя. `main` не трогать; в `main` — только по явному разрешению после зелёных проверок и CI. Force-push запрещён.
18. **Тестирование обязательно**: перед просьбой о коммите — `lint`, `typecheck`, `test`, `build`; запрет skip/only/ослабления тестов; отчёт по формату из `CLAUDE.md`.
19. **Делегирование**: Claude Code — оркестратор; простые изолированные задачи — локальной модели Ollama через MCP (`qwen2.5-coder:7b`); архитектура, безопасность, CI/CD, сложная интеграция и приёмка — Claude Code. В отчётах указывать исполнителя каждой части.
20. **AI-скилы**: проектные скилы в `.claude/skills/` (13 шт.), инвентаризация — `docs/skills-inventory.md`. `code-review` скопирован как `milo-code-review` (конфликт имён). Недостающие скилы созданы по официальной документации, а не скачаны.
21. **Фичи продуктов**: `add-product` и `edit-product` из первоначального плана объединены в `features/manage-product` (общая форма; FSD запрещает импорт между фичами). `filterProducts` перенесён в `entities/product` для переиспользования.

## Частичная переделка (2026-11-05)

Утверждено пользователем вместе с планом переделки (этапы: `feat/brand-mark-m` → `feat/pantry-in-stock` → `feat/recipes` → `feat/cook-recipe`).

22. **Знак — строчная «м» из двух арок с мятной точкой** (форма из концепции B «Рост») в цветах «Орбиты»: ультрамариновый скруглённый квадрат (rx 12 из 48), белая «м» обводкой 4.6, мятная точка; тёмная версия — фон `#6F7BFF`, «м» `#0B0C14`. Касается логотипа, иконок PWA и фавиконов. Заменяет знак из решения №3.
23. **Кладовая показывает только то, что в наличии** (`stock > 0`); вкладок «Все / В наличии» нет. Поиск ищет по всем известным продуктам; из результатов продукт можно добавить в покупки или сразу в кладовую. Позже — внешний API продуктов и добавление по штрихкоду (не выбран, отдельное решение).
24. **Навигация: Сегодня · Рецепты · Кладовая · Покупки** _(состав вкладок заменён решением №28)_, профиль — кнопкой в шапке. Раздел «Дневник» убирается; записи о съеденном остаются на «Сегодня», `/diary` перенаправляется на `/`. Заменяет решение №8.
25. **Раздел «Рецепты»** — вкладки «Рецепты» (все), «Приготовленные» (готовые блюда с остатком порций: сварил 6, съел 2 → осталось 4; порцию можно записать в «Сегодня») и «История» (журнал готовки и съеденного). Варианты с 2 и 3 вкладками сравнили по скриншотам; **выбраны 3 вкладки** (2026-11-05). Ингредиенты — только продукты кладовой, количество в единице продукта.

## Доработки после переделки (2026-11-05)

Порядок работ, заданный пользователем: доработки интерфейса (№26–28) → скан штрихкодов → **merge всего в `main` перед началом бэкенда** → бэкенд.

26. **Быстрая правка остатка в кладовой**: нажатие на «В наличии: …» в карточке открывает окно — точное число, кнопки −/+ (шаг 1 шт / 50 г / 100 мл), «Закончилось» (0) и «Сохранить».
27. **«Добавить еду» на «Сегодня»** показывает, кроме продуктов, приготовленные блюда (порция списывается с блюда) и рецепты: выбранные порции рецепта записываются с КБЖУ по рецепту, а продукты на эти порции списываются из кладовой (с переключателем «списать», как у продуктов).
28. **Навигация: Сегодня · Рецепты · Кладовая · Профиль.** «Покупки» — вторая вкладка внутри «Кладовой». Кнопка в шапке страниц (где была ссылка на профиль) ведёт на страницу «Приложение» (`/app`): установка PWA (перенос карточки из профиля), инструкции для iPhone и Android, блок «приложение для App Store и Google Play — скоро». Заменяет состав вкладок из решения №24.

## Шапка, профиль и покупки (2026-11-05)

29. **Шапка на каждой странице** (`widgets/app-header` в `RootLayout`): знак и слово MILO (на экранах уже 360 px — только знак), счётчик «съедено / норма ккал» за сегодня с маленьким кольцом (при превышении — красный; ведёт на «Сегодня»), кнопка «Приложение». Кнопка из ряда над заголовком страниц убрана.
30. **Профиль и расчёт нормы**: анкета при первом запуске (с «Позже» → карточка на «Сегодня»): пол, возраст, рост, вес, активность, цель (похудеть / удерживать / набрать). Формула Миффлина — Сан Жеора × коэффициент активности 1,2–1,9; цель: −500 ккал (не ниже 1200 Ж / 1500 М) / 0 / +300; БЖУ: белок 1,6 г/кг (похудеть, набрать) или 1,2 г/кг (удерживать), жиры 30 % ккал, углеводы — остаток. Данные меняются в «Профиле»; своя норма вручную остаётся.
31. **Предложение «мало»**: когда остаток падает ниже минимума или до нуля — всплывающее предложение «… заканчивается · В покупки / ✕»; само ничего не добавляется.
32. **Галочка в покупках** — свой стиль (круг в цвете бренда, белая отметка).
33. **«Мои данные» в профиле — аккордеон** (`shared/ui/Collapsible` на `<details>/<summary>`): заполненный профиль свёрнут до сводки «Женщина, 25 лет · 165 см · 60 кг · Лёгкая активность · Похудеть», пустой — раскрыт.
34. **Скан штрихкодов отложен** (2026-11-05): без новой зависимости `barcode-detector` сканер на iPhone не работает — пользователь выбрал «пока без сканера». Когда вернёмся: источник данных по штрихкоду — **Open Food Facts** (утверждено; лицензия ODbL — указывать источник), через интерфейс «источник продуктов».
35. **Порядок дальше** (2026-11-05): проект на GitHub → CI-пайплайн (lint, typecheck, test, build) → merge всего в `main` → бэкенд.
36. **Репозиторий и CI** (2026-11-05): публичный https://github.com/AlexGdove/MILO; автор коммитов — noreply GitHub (`238381513+AlexGdove@users.noreply.github.com`, история переписана до первого push с разрешения пользователя). CI — GitHub Actions (npm ci → lint → format → typecheck → test → build). Dependabot — еженедельно в `dev`, **без мажорных версий** (смена стека — только с одобрения).
37. **Бэкенд** (2026-11-05): стек — Node 22, NestJS 12, PostgreSQL, Prisma, REST `/api/v1`, WebSocket, Docker Compose (B-1…B-5). **Регистрации нет**, личные данные остаются на устройстве; сервер хранит только опубликованные пользователем рецепты и анонимные обращения в поддержку, авторство — анонимный ключ устройства, модерация и поддержка — операторы в Telegram (B-6…B-11). Подробно — `docs/backend/DECISIONS.md`.
38. **Приготовленное блюдо — в порциях или граммах** (запрос пользователя 2026-11-05): в «Добавить еду» переключатель «Порции / Граммы». В граммах списывается дробная часть порции (вес / вес порции), остаток блюда может быть дробным (точность 0.001 порции, показ до десятых: «2,5 порц.»; остаток меньше 0.01 порции = доедено). В записи — ровно введённый вес; при удалении записи дробные порции возвращаются блюду. Если целой порции не осталось — только граммы. «Съесть порцию» в «Приготовленных» остаётся в порциях (при остатке меньше порции доедает остаток).
39. **Переключатель темы в «Профиле»** (запрос пользователя 2026-11-05): раздел «Оформление» — «Авто / Светлая / Тёмная» (по умолчанию «Авто» = как в системе). Выбор хранится на устройстве (`milo:theme`, zustand persist через `shared/lib/storage`), применяется атрибутом `data-theme` на `<html>` (`features/switch-theme`, хук в `App`); встроенный скрипт в `index.html` ставит сохранённую тему до первой отрисовки, чтобы не мигала светлая.
