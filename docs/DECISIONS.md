# Принятые решения MILO

Журнал решений, которые **утвердил пользователь** (или которые следуют из его явных требований). Предложения без утверждения сюда не попадают — они в `docs/TASKS.md` («Открытые вопросы»). Новое решение добавляется в конец с датой; отменённое не удаляется, а помечается «Заменено решением №…».

Даты — 2026-11-04 (одна рабочая сессия), если не указано иное.

## Продукт и бренд

1. **Название — MILO** (Meal Intelligence & Lifestyle Organizer). Существующее приложение подсчёта калорий развивается как MILO, а не создаётся заново. Главное слово — MILO, расшифровка не обязательна везде.
2. **Концепция продукта**: шире подсчёта калорий — дневник, кладовая, рецепты, список покупок. Ключевая идея: пользователь видит, что есть дома; готовка по рецепту списывает продукты; закончившееся и недостающее можно добавить в покупки **или пропустить — по решению пользователя, без автодобавления**.
3. **Айдентика**: палитра концепции C «Орбита» + знак концепции A «Пропорция» (три столбика БЖУ, силуэт «M»). Концепции: https://claude.ai/artifact/KPXspyqYRa6yFwPstU5i5M. Детали — `docs/brand.md`.
4. **Шрифты**: Onest (текст/UI) и Unbounded (логотип, крупные числа), подключение пакетами `@fontsource` (офлайн в PWA). Зависимость одобрена, ещё не установлена.
5. **Единицы в кладовой**: г, мл, шт (для шт — вес одной штуки); минимальный остаток на продукт.
6. **Рецепты**: сначала свои, локально; внешний API и общая база пользователей — позже, через общий интерфейс `RecipeSource`. Конкретный API не выбран.
7. **Дизайн-система** (из утверждённого плана): двухслойные токены в `frontend/src/app/styles/variables.css` (примитивы `--milo-*` + семантические `--color-*`, `--font-*`, `--space-*`, `--radius-*`, `--shadow-*`), светлая и тёмная тема (`prefers-color-scheme`, готовность к `[data-theme]` без UI-переключателя), литералы в CSS-модулях запрещены. Цвета БЖУ: белки — светлый ультрамарин, жиры — янтарь `#FFB84D`, углеводы — лаванда `#9B8CFF`; мята `#3CCB9A` — только подсказки.
8. **Навигация после шага «Список покупок»**: Сегодня · Дневник · Рецепты · Кладовая · Покупки; профиль — из шапки. Раздел «Продукты» переименовывается в «Кладовая» (`/pantry`, редирект со `/products`).

## Архитектура и стек

9. **Монорепо npm workspaces**: `frontend/` (React PWA), `backend/`, `mobile/`. Backend и mobile — заготовки; их стек **не выбран** (пользователь выбрал «пока только заготовка»).
10. **Фронтенд**: Vite 8, React 18, TypeScript 5.9 (зафиксирован `~5.9`: TS 7 мог не поддерживаться typescript-eslint), react-router-dom 7, Zustand 5, CSS Modules, vite-plugin-pwa 2. Без UI-библиотек.
11. **FSD** (`app → pages → widgets → features → entities → shared`), импорт слайсов только через `index.ts`, алиас `@/`. Контроль — ESLint 9 flat config + `eslint-plugin-boundaries` + `no-restricted-imports`; порядок импортов — `eslint-plugin-import-x`; Prettier.
12. **Хранение данных**: локально, Zustand `persist` только через `shared/lib/storage` (`persistStorage`, `storageKey`). Префикс ключей `milo:`; данные со старого префикса `calorie-tracker:` переносятся при первом чтении.
13. **Изменение формы сохранённых данных** — только с повышением `version` и функцией `migrate` + тестом (иначе Zustand отбрасывает данные пользователя; подтверждено тестом 2026-11-04).
14. **Тесты**: Vitest + React Testing Library (не Jest), jsdom.
15. **Серверное состояние** (когда появится бэкенд/API) — TanStack Query; большие списки — TanStack Virtual. **Сейчас не установлены**, добавление требует отдельного одобрения. Redux не использовать.
16. **Одобренные зависимости из плана**: `@fontsource/onest`, `@fontsource/unbounded` (ещё не установлены); `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/dom`, `@testing-library/jest-dom`, `@testing-library/user-event` (установлены). Другие — только с одобрения.

## Процесс

17. **Git** (раздел 11 требований): `main` — стабильная, `dev` — интеграция; задачи — в рабочих ветках от `dev`. Коммиты, merge в `dev`, push, операции с ветками вне схемы — только с явного разрешения пользователя. `main` не трогать; в `main` — только по явному разрешению после зелёных проверок и CI. Force-push запрещён.
18. **Тестирование обязательно**: перед просьбой о коммите — `lint`, `typecheck`, `test`, `build`; запрет skip/only/ослабления тестов; отчёт по формату из `CLAUDE.md`.
19. **Делегирование**: Claude Code — оркестратор; простые изолированные задачи — локальной модели Ollama через MCP (`qwen2.5-coder:7b`); архитектура, безопасность, CI/CD, сложная интеграция и приёмка — Claude Code. В отчётах указывать исполнителя каждой части.
20. **AI-скилы**: проектные скилы в `.claude/skills/` (13 шт.), инвентаризация — `docs/skills-inventory.md`. `code-review` скопирован как `milo-code-review` (конфликт имён). Недостающие скилы созданы по официальной документации, а не скачаны.
21. **Фичи продуктов**: `add-product` и `edit-product` из первоначального плана объединены в `features/manage-product` (общая форма; FSD запрещает импорт между фичами). `filterProducts` перенесён в `entities/product` для переиспользования.
