## На подтверждение (решения шага 7, принятые Claude Code в рамках архитектуры)

Не внесены в `DECISIONS.md`, пока пользователь их не утвердит:

- Профиль — круглая кнопка в верхнем ряду страницы справа (`widgets/profile-link`, через `PageLayout.eyebrow`); на «Сегодня» — напротив логотипа. Вариант «в ряду заголовка» давал переполнение на 360 px.
- Позиция списка покупок всегда ссылается на продукт кладовой (свободных позиций без продукта нет) — иначе нечего переносить в остатки.
- Подсказки «Заканчиваются» и бейджи — только для отслеживаемых продуктов (`minStock > 0`) ниже минимума. Закончившиеся продукты без минимума показывают «Нет в наличии» без подсказки.
- Количество по умолчанию: недостающее до минимума; если минимум набран — сам минимум; без минимума — 500 г / 1000 мл / 1 шт. Пользователь меняет его в диалоге.
- Повторное добавление продукта суммирует количество и снимает отметку «куплено»; при сменившейся единице количество заменяется.
- «Перенести купленное» не трогает позиции удалённых продуктов и позиции со сменившейся единицей — они остаются с пометкой; их можно удалить вручную.
- Новый токен `--icon-size-sm: 18px` в `variables.css`.

## Известные ограничения и риски

- Повышение `version` persist-стора без `migrate` уничтожит данные пользователей (подтверждено тестом).
- Локальная модель `qwen2.5-coder:7b` теряет пункты длинных ТЗ — давать короткие задания и всегда проверять.
- До шага 3 интерфейс зелёный при ультрамариновом theme-color.
- Допущение «1 мл ≈ 1 г» задокументировано в коде (`shared/lib/units.ts`) и в UI (подсказка в форме продукта для жидкостей).
- Шаг «v1 → v2» в миграции продуктов дублирует значения по умолчанию из нормализации (`unit: g`, `minStock: 0`), поэтому тест не отличит его удаление; данные пользователя при этом всё равно сохраняются.
