# ADR-0002. Снимок ингредиентов в публичном рецепте

Статус: **заменено** (2026-11-06, ADR-0005): публикации рецептов нет. Было: принято (2026-11-05). Связано: B-7, аудит R5.

## Контекст

В клиенте ингредиент рецепта — это ссылка `productId` на продукт кладовой пользователя. Кладовая на сервер не передаётся (B-6), а у другого пользователя таких продуктов нет.

## Решение

- Публичный рецепт хранит **самодостаточный снимок** каждого ингредиента: название, количество на весь рецепт, единицу, вес штуки (для `pcs`), КБЖУ на 100 г. Остаток, минимум и id продуктов не передаются.
- Сервер сам вычисляет КБЖУ на порцию по тем же правилам, что клиент (`toGrams`: мл ≈ г, шт × вес штуки; `recipeNutrition`), и хранит результат для каталога. Совпадение формул проверяется общими тест-кейсами на клиенте и сервере.
- При правке рецепта автор отправляет новый снимок целиком. Изменения продукта в кладовой автора опубликованный рецепт не меняют, пока автор не опубликует его заново.
- «Добавить себе» создаёт локальную копию и сопоставляет ингредиенты с продуктами кладовой по названию и единице. Если подходящего продукта нет, создаётся новый с остатком 0 и КБЖУ из снимка.

## Последствия

- Каталог работает без доступа к данным автора, и удаление продукта у автора ничего не ломает.
- Одинаковые продукты в разных рецептах дублируются (название и КБЖУ). Это приемлемо до появления общего каталога продуктов (Open Food Facts, решение №34).
