# ADR-0001. Анонимный ключ устройства вместо аккаунтов

Статус: принято (2026-11-05). Связано: B-6, B-8, B-10.

## Контекст

Владелец решил: регистрации и email нет, личные данные остаются на устройстве. При этом автор должен иметь возможность изменить или снять свой опубликованный рецепт, а пользователь — продолжить переписку с поддержкой. Значит, нужна идентичность без личных данных.

## Решение

- Сервер выдаёт ключ `mk_<base64url(32 случайных байта)>` по `POST /device-keys`. Ключ показывается клиенту один раз, хранится локально (`shared/lib/storage`) и передаётся в `X-Device-Key`.
- В базе хранится только `SHA-256(ключ)`. Argon2 и подобные медленные хэши не нужны: они защищают пароли с низкой энтропией, а у ключа 256 бит энтропии, подбор невозможен. Благодаря быстрому хэшу проверка — поиск по уникальному индексу.
- Ключ создаётся лениво, при первой публикации, жалобе или обращении. Пользователь, который только читает каталог, ключа не получает.
- Ключ — это право на запись своих рецептов и обращений. Оператор может заблокировать его за спам.

## Последствия

- Потеря устройства или очистка данных браузера — потеря управления рецептами и обращениями. Опубликованные рецепты остаются в каталоге. Перенос ключа на другое устройство — вне объёма (владелец выбрал вариант без кода переноса).
- Ограничить злоупотребления можно только лимитами по IP и ключу и модерацией (`architecture.md` §5).
- Нет JWT, сессий, refresh-токенов, cookie, email: `@nestjs/jwt`, `argon2`, `nodemailer`, `cookie-parser` не ставятся (B-11).
