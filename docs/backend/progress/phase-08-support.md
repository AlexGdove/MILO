# Этап 8. Поддержка на основном сервере — отчёт

Дата: 2026-11-06. Ветка: `feat/backend-support` (от `dev` @ `8c7ec9b`). Решение — B-19.

## 1. Что сделано

- **REST** `/api/v1/support/tickets` — 6 маршрутов из `api.md`:
  - создать (с первым сообщением), список (по последней активности, курсор), обращение, сообщения (`?after=`, `limit`), написать, закрыть;
  - все с `DeviceKeyGuard`; заблокированный ключ тоже может писать — путь обжалования;
  - `Idempotency-Key` на создании и сообщении; лимиты `ticketCreate`, `ticketMessage`, `supportRead`.
- **Статусы**: сообщение пользователя → `open` (переоткрывает закрытое), ответ оператора → `answered`, закрытие → `closed` (повтор ничего не меняет).
- **Outbox** для бота поддержки (этап 9): `ticket.created`, `ticket.message_from_user`, `ticket.closed` — в одной транзакции с изменением, только id.
- **WebSocket** — Socket.IO, путь `/socket.io`, пространство `/support`:
  - ключ передаётся в `auth`, проверка при рукопожатии; комната устройства;
  - события `message.created` и `ticket.updated` — только после фиксации транзакции;
  - лимит подключений — 30 в минуту с IP;
  - CORS — из `CORS_ORIGINS` (`MiloIoAdapter`).
- **Ответ оператора** — `SupportService.addOperatorReply` (для бота, этап 9): только активный оператор, имя оператора в сообщении.
- **Общая пагинация** (`src/common/pagination/page.ts`): `PageQueryDto` и `cursorPage` по `createdAt` или `updatedAt`. Продукты переведены на неё; в курсоре поле `createdAt` переименовано в `at`.
- Время обращений и сообщений задаёт приложение (мс), как у продуктов.
