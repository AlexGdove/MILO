# Этап 5. Ключ устройства и защита — отчёт

Дата: 2026-11-06. Ветка: `feat/backend-device-key` (от `dev` @ `785a80e`).

## 1. Что сделано

- **Ключ устройства** (`src/modules/device-keys/`, ADR-0001):
  - `POST /api/v1/device-keys` → `201 { key }`: ключ `mk_` + 32 байта base64url, в базе только SHA-256;
  - `DELETE /api/v1/device-keys/me` → `204`: удаляет ключ и каскадом всё, что связано с устройством;
  - `DeviceKeyGuard` + `@CurrentDeviceKey()`. Нет заголовка → `401 device_key_required`; неверный формат или неизвестный ключ → `401 device_key_invalid`; заблокированный ключ на запись → `403 device_key_blocked` (чтение разрешено);
  - `last_seen_at` обновляется не чаще раза в час.
- **Лимиты** (`src/modules/rate-limit/`, `architecture.md` §5, B-16):
  - глобальный `RateLimitGuard`: общий лимит 600 в минуту по IP на каждый запрос, плюс лимит действия из `@RateLimit(name)`;
  - правила: выдача ключа, каталог, публикация, правка, жалоба. Лимиты поддержки — в `support/` (B-15);
  - скользящее окно — атомарный Lua-скрипт в Redis, время берётся по часам Redis;
  - превышение → `429 rate_limited` + `Retry-After` в секундах;
  - Redis недоступен → `503 service_unavailable`;
  - IPv6 считается подсетью /64, IPv4-mapped — как IPv4;
  - ключ устройства в Redis не попадает — только хэш.
- **Redis**:
  - `compose.yaml`: Redis 8 alpine, без сохранения на диск;
  - CI: Redis как service, `TEST_REDIS_URL`;
  - `RedisService` на `ioredis`: фоновое подключение, ответ или ошибка за 1 с;
  - `/health/ready` проверяет базу и Redis, `/health` — без общего лимита.
- **ENV**: `REDIS_URL` (обязательна, `redis://` или `rediss://`), `TRUST_PROXY` (число доверенных прокси 0–10, по умолчанию 0 — `X-Forwarded-For` не учитывается).
- **Тесты**: global-setup выставляет `REDIS_URL` из `TEST_REDIS_URL` и запрещает базу Redis 0, потому что тесты очищают базу (`FLUSHDB`).

## 4. Решения для подтверждения

- `DELETE /device-keys/me` разрешён и заблокированному ключу: право стереть свои данные не зависит от блокировки. На это действие — лимит `recipeWrite` (60 в час).
- Redis недоступен → запросы отклоняются (503), а не пропускаются без лимитов.
- `blockDuration` нет: после отказа запрос проходит, когда старейший запрос выйдет из окна.
