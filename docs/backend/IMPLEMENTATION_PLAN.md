# План реализации backend MILO

Источник требований: промт владельца «Разработка полноценной серверной части MILO» (2026-11-05). Аудит — `audit.md`. Текущее состояние — `PROGRESS.md`, нерешённое — `BLOCKERS.md`, решения — `DECISIONS.md` (ADR — `adr/`).

Правила: всё локально (развёртывание запрещено до отдельного подтверждения); каждый этап — отдельная ветка от `dev`, отчёт в `progress/phase-NN-*.md`, переход дальше — только при выполненных критериях; коммит/merge — с решения владельца; перед работой — проверка Ollama (простые изолированные части — ей, проверка и интеграция — Claude Code).

**Изменение 2026-11-05 (B-15):** поддержка выносится в отдельный сервис `support/` на отдельном VPS со своей базой. Таблицы поддержки (`support_tickets`, `support_messages`, связь `telegram_message_links.ticket_id`) из схемы `backend/` будут удалены отдельной миграцией (этап 5 или 6); этапы 11–14 делаются для двух сервисов (два образа, два развёртывания, бэкапы двух баз, CI для обоих в той же проверке).

PostgreSQL в Docker поднимается уже на этапе 4 (нужен для миграций и тестов); этап 11 доводит инфраструктуру до production-уровня.
