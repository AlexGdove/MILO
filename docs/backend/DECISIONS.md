# Решения backend MILO

Журнал решений по серверной части. Общие решения проекта — `docs/DECISIONS.md` (№1–36). Подробные обоснования — ADR в `adr/` (с этапа 2).

| #    | Решение                                                                                                                                                                                                                                                                                                          | Основание                                                            | Дата       |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ---------- |
| B-1  | Стек: Node.js 22 LTS, TypeScript, NestJS 12, PostgreSQL, Prisma, REST `/api/v1`, WebSocket для чата, Docker Compose локально; развёртывание запрещено до подтверждения                                                                                                                                           | промт владельца                                                      | 2026-11-05 |
| B-2  | Архитектура — модульный монолит; Kafka и Kubernetes — не сейчас, архитектура допускает их позже (доменные события + outbox)                                                                                                                                                                                      | промт владельца, аудит R12                                           | 2026-11-05 |
| B-3  | Тесты backend — **Jest** (явное требование владельца); frontend остаётся на Vitest                                                                                                                                                                                                                               | промт владельца, аудит R2                                            | 2026-11-05 |
| B-4  | Prisma — стабильная 7.10.1; предрелиз 8.0 не используется                                                                                                                                                                                                                                                        | аудит R13                                                            | 2026-11-05 |
| B-5  | Имя обязательной проверки CI `lint · typecheck · test · build` не меняется — backend добавляется в ту же проверку                                                                                                                                                                                                | правило ветки `main`, аудит R14                                      | 2026-11-05 |
| B-6  | Нет регистрации, входа и email. Личные данные (профиль, кладовая, дневник, покупки, личные рецепты) на сервер не передаются — остаются на устройстве; офлайн-PWA сохраняется полностью                                                                                                                           | ответы владельца В1, В3                                              | 2026-11-05 |
| B-7  | На сервере только рецепты, которые пользователь сам опубликовал; личные рецепты — только на устройстве                                                                                                                                                                                                           | ответ владельца                                                      | 2026-11-05 |
| B-8  | Авторство — анонимный ключ устройства: сервер выдаёт случайный секрет (≥ 256 бит), хранит только его хэш SHA-256; клиент хранит ключ локально (через `shared/lib/storage`) и передаёт в заголовке. Ключ даёт право изменить или снять свои рецепты и вести свои обращения. Потеря устройства — потеря управления | ответ владельца                                                      | 2026-11-05 |
| B-9  | Модерация: рецепт публикуется сразу; «Пожаловаться» → жалоба операторам в Telegram; оператор может скрыть рецепт                                                                                                                                                                                                 | ответ владельца                                                      | 2026-11-05 |
| B-10 | Поддержка: анонимный чат в приложении (экран в профиле) по ключу устройства; операторы отвечают только из Telegram                                                                                                                                                                                               | ответы владельца В4, В5                                              | 2026-11-05 |
| B-11 | Зависимости `IMPLEMENTATION_PLAN.md` §10 одобрены целиком, включая `@tanstack/react-query`; ставятся по мере этапов. Ненужные при B-6 (`@nestjs/jwt`, `argon2`, `nodemailer`, `cookie-parser`) не ставятся                                                                                                       | ответ владельца В2                                                   | 2026-11-05 |
| B-12 | Backend — ES-модули (`"type": "module"`, `NodeNext`, импорты с `.js`). NestJS 12 публикуется только как ESM; Jest (B-3) запускается в ESM-режиме (`--experimental-vm-modules`, ts-jest `useESM`). Vitest и смена Node не потребовались                                                                           | этап 3: Jest на Node 22 не загружает ESM-пакеты Nest через `require` | 2026-11-05 |

Предложения, ожидающие решения владельца, — `BLOCKERS.md`.
