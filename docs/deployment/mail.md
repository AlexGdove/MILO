# Свой почтовый сервер MILO (решение №70)

## Зачем и как устроено

Письма с кодами (подтверждение почты при регистрации, сброс пароля) отправляет свой почтовый сервер на VPS — бесплатно, без сторонних сервисов.

Сервис `mail` в `compose.prod.yaml` — образ `boky/postfix:5.2.1-alpine`, только отправка, наружу порты не открыты. Backend передаёт ему письмо по внутренней сети (порт 587); сервер подписывает письмо DKIM и доставляет получателю по порту 25. Исходящий порт 25 у VPS открыт (проверено 2026-11-11: Яндекс, Mail.ru и Gmail отвечают).

Отправитель писем — `MILO <noreply@milo-app.ru>`, имя почтового сервера — `mail.milo-app.ru`.

## Что нужно один раз

Шаги — по порядку.

1. **Выкатить версию с сервисом `mail`:**

   ```bash
   cd ~/milo && git pull --ff-only origin main && docker compose -f compose.prod.yaml up -d --build --wait
   ```

2. **Достать DKIM-ключ.** Он создаётся при первом запуске и хранится в томе `mail-dkim` (при перезапуске не меняется):

   ```bash
   docker compose -f compose.prod.yaml exec mail cat /etc/opendkim/keys/milo-app.ru.txt
   ```

   В DNS вставляется всё, что в кавычках, одной строкой — без кавычек и пробелов между частями: `v=DKIM1; h=sha256; k=rsa; s=email; p=...`.

3. **Сменить обратную запись (PTR).** В панели FirstVDS, в разделе IP-адресов сервера, для `141.133.181.77` вместо `fumcka.fvds.ru` указать `mail.milo-app.ru`. Без этого Gmail и Mail.ru отправят письма в спам или отклонят.

4. **Добавить записи DNS** (панель FirstVDS → DNS домена `milo-app.ru`). Как попасть: личный кабинет https://my.firstvds.ru → «Товары» → «Виртуальные серверы» → у сервера «Инструкция» → блок **DNSmanager** (адрес, логин, пароль) → в DNSmanager домен `milo-app.ru` → записи (путь до DNSmanager — по справке FirstVDS; по нему владелец добавил записи BIMI 2026-11-13):

   | Тип | Имя               | Значение                            | Зачем                                                                                     |
   | --- | ----------------- | ----------------------------------- | ----------------------------------------------------------------------------------------- |
   | A   | `mail`            | `141.133.181.77`                    | адрес почтового сервера (запись `A *` уже покрывает `mail`, но явная надёжнее)            |
   | TXT | `@`               | `v=spf1 ip4:141.133.181.77 -all`    | SPF: отправлять письма домена можно только с нашего сервера                               |
   | TXT | `mail._domainkey` | ключ из шага 2 (`v=DKIM1; …; p=…`)  | DKIM: подпись писем                                                                       |
   | TXT | `_dmarc`          | `v=DMARC1; p=none; adkim=s; aspf=s` | DMARC: пока только наблюдение; через месяц без проблем можно ужесточить до `p=quarantine` |

5. **Дождаться DNS** (до нескольких часов) и проверить ключ:

   ```bash
   nslookup -type=TXT mail._domainkey.milo-app.ru 8.8.8.8
   ```

6. **Включить отправку.** В `~/milo/.env` (права 600) добавить:

   ```text
   AUTH_CODE_SECRET=<результат команды openssl rand -base64 48>
   EMAIL_TRANSPORT=smtp
   ```

   и перезапустить backend:

   ```bash
   docker compose -f compose.prod.yaml up -d backend
   ```

   Без этих настроек регистрация и сброс пароля отвечают «временно недоступно»; вход паролем работает.

## Проверка

Зарегистрироваться в приложении на свою почту — Яндекс, Mail.ru и Gmail — и убедиться, что письмо пришло. В Gmail «Показать оригинал»: должно быть `SPF: PASS`, `DKIM: PASS`, `DMARC: PASS`.

## Логи и очередь

```bash
docker compose -f compose.prod.yaml logs mail --tail 50
```

- `status=sent` — доставлено;
- `status=deferred` — сервер получателя попросил повторить позже, повтор будет сам;
- `status=bounced` — отклонено.

Очередь писем:

```bash
docker compose -f compose.prod.yaml exec mail postqueue -p
```

## Значок MILO рядом с письмом (BIMI)

Без настройки почтовые клиенты показывают рядом с отправителем кружок с первой буквой («М»). Значок не вкладывается в письмо — его берут из DNS по стандарту BIMI.

Знак лежит на сайте: `https://milo-app.ru/bimi.svg` — квадрат ультрамарина `#2F3BD9` на всю площадь (почтовики сами обрезают его в круг), белая «м» из двух арок и мятная точка. Формат SVG Tiny PS обязателен для BIMI. Файл — `frontend/public/bimi.svg`, попадает на сайт при обычной выкатке.

После выкатки версии с `bimi.svg` (панель FirstVDS → DNS домена `milo-app.ru`):

1. **Проверить, что файл открывается:**

   ```bash
   curl -I https://milo-app.ru/bimi.svg
   # ожидается: 200 и content-type: image/svg+xml
   ```

2. **Добавить запись BIMI и ужесточить DMARC:**

   | Тип | Имя             | Значение                                       | Зачем                                                                                                                        |
   | --- | --------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
   | TXT | `default._bimi` | `v=BIMI1; l=https://milo-app.ru/bimi.svg; a=;` | где лежит значок; `a=` пустое — сертификата товарного знака (VMC) нет                                                        |
   | TXT | `_dmarc`        | `v=DMARC1; p=quarantine; adkim=s; aspf=s`      | заменить прежнее `p=none`: BIMI работает только при `quarantine` или `reject`; наши письма проходят SPF и DKIM — не затронет |

3. **Проверить запись:**

   ```bash
   nslookup -type=TXT default._bimi.milo-app.ru 8.8.8.8
   ```

**Где покажется.** Gmail показывает значок только с платным сертификатом VMC (нужен зарегистрированный товарный знак) — у нас его нет, в Gmail значка не будет. Mail.ru и Яндекс — проверить на практике после настройки. Почтовики кэшируют значок — он может появиться не сразу.

**Отменить:** удалить запись `default._bimi`, DMARC вернуть на `p=none`.

## Риски и запасной вариант

- **Репутация.** У нового IP нет истории — первые письма могут попадать в «Спам», особенно в Gmail. Под полем кода в приложении есть подсказка проверить «Спам». При небольших объёмах репутация растёт за несколько недель.
- **Чёрные списки.** Проверить IP: mxtoolbox.com → Blacklist Check.
- **Запасной вариант.** Если доставка остаётся плохой — Unisender Go: способ отправки выбирается настройкой `EMAIL_TRANSPORT`, под их API нужна доработка.
- **Что видит пользователь.** Адрес не принимает почту (нет домена или ящика) — «На этот адрес нельзя отправить письмо — проверьте почту». Почтовый сервер недоступен — «Не получилось отправить письмо. Попробуйте чуть позже».
