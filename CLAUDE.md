# Правила проекта MILO

Продукт и бренд: `docs/product.md`, `docs/brand.md` (MILO — Meal Intelligence & Lifestyle Organizer).

## Начало каждой сессии

1. Прочитать этот файл, затем `docs/CURRENT_STATE.md`, `docs/TASKS.md`, `docs/DECISIONS.md`, `docs/ROADMAP.md`.
2. Проверить `git branch --show-current` и `git status`; сверить с `CURRENT_STATE.md`.
3. Продолжать с последнего зафиксированного состояния. Не начинать заново и не пересматривать решения из `DECISIONS.md` без запроса пользователя; открытые вопросы из `TASKS.md` не считать решёнными.
4. В конце сессии (или по просьбе) обновить `CURRENT_STATE.md`, `TASKS.md`, при новых решениях — `DECISIONS.md`, при изменении плана — `ROADMAP.md`.

- Монорепо на npm workspaces: `frontend/` (React PWA), `backend/`, `mobile/` (пока заготовки).
- Фронтенд строго по FSD: `app → pages → widgets → features → entities → shared`, импорт слайсов только через `index.ts`, алиас `@/` = `frontend/src`.
- Стили — CSS Modules + CSS-переменные из `frontend/src/app/styles/variables.css`. Mobile-first.
- Данные пока хранятся локально (zustand persist) — доступ к хранилищу только через `shared/lib/storage`.
- UI-тексты на русском.
- AI-скилы проекта — в `.claude/skills/` (инвентаризация: `docs/skills-inventory.md`). Перед задачей выбирать релевантные (React/TS, Zustand, тесты, git, CI); скилы не разрешают менять стек или ставить зависимости без одобрения.
- Тесты: frontend — Vitest + React Testing Library (не Jest); backend — Jest + supertest (решение B-3, `docs/backend/DECISIONS.md`).

## Git (строгие правила, раздел 11 требований пользователя)

- Ветки: `main` — стабильная, `dev` — интеграция. Каждая задача — рабочая ветка **от `dev`** (`feat/`, `fix/`, `chore/`, `refactor/`, `docs/`, `test/`, `ci/`).
- **`main` не трогать никогда**: никаких merge, rebase, cherry-pick, push, правок в рабочем дереве на `main`. В `main` изменения попадают только по явному разрешению пользователя после зелёных тестов, typecheck, lint, build, CI и просмотра результатов. Зелёный CI — не разрешение.
- **Без явного разрешения пользователя не делать**: коммиты, merge в `dev`, push, создание/переключение/удаление веток вне согласованной схемы, изменение истории, force-push, изменение настроек репозитория и защиты веток.
- Перед задачей: `git branch --show-current` и `git status`. Если ветка `main` — остановиться.
- **Версия** (решение №48): 1.0.0 — первый релиз. Каждая новая функция или исправление повышает последнюю цифру — `npm run version:patch` в рабочей ветке перед коммитом (1.0.0 → 1.0.1); major/minor — только по решению пользователя. Версия одна на всё: package.json, Android, iOS, «MILO x.y.z» внизу настроек.
- Перед коммитом показать пользователю diff/сводку и результаты проверок, затем спросить разрешение.

## Тестирование (обязательно)

- Перед просьбой о коммите/merge: `npm run lint && npm run typecheck && npm test && npm run build` — все без ошибок.
- Запрещено: skip/only, удаление или ослабление тестов, отключение наборов, фиктивные проверки, изменение конфигурации тестов ради зелёного результата, сообщение об успехе без реального запуска.
- Упал тест → остановиться, показать имя теста и ошибку, найти причину, предложить план исправления.
- Изменение существующего теста — только при изменении требований или ошибке в самом тесте, с объяснением «что проверял / что проверяет теперь / почему не маскирует ошибку». Удаление теста — только с отдельного разрешения.
- После каждой задачи — отчёт: всего / прошло / упало / пропущено тестов, ошибки и причины; статусы TypeScript, ESLint, тестов (Vitest), build, CI. Не запускалось — прямо сказать почему.

## Делегирование локальной модели (Strata через MCP)

Claude Code — оркестратор: разбивает работу, готовит ТЗ, проверяет и интегрирует результат, отвечает за итог. Простые изолированные задачи по умолчанию отдаются локальной модели.

- Инструменты: MCP-сервер `strata` (`strata_status`, `strata_chat`; код — `F:\AI-DEV\infrastructure\strata-mcp`). Второе подключение не создавать. Модель: Qwen3.6-35B-A3B UD-Q4_K_XL, контекст 32K (проверено 2026-11-09; Ollama больше не используется). Перед делегированием вызвать `strata_status`; если движок не отвечает — сказать пользователю и предложить альтернативу.
- Запуск движка: конфиг Strata по умолчанию (контекст 131072 + vision) не помещается в 12 ГБ VRAM (RTX 3060) — используется копия с `--max-context 32768 --mtp 1` без `--vision`, порт 8080. Первая загрузка весов занимает 10+ минут.
- **Кластерный принцип**: модель получает только нужный кластер — файл(ы), типы и контракты соседей, которых касается задача (до ~8K токенов). Целиком проект знает и держит в голове Claude Code; модель его не изучает и ничего не додумывает вокруг кластера.
- **Режим мышления**: по умолчанию модель «думает» (в 3–4 раза больше токенов, 30–160 с на задачу). Простые задачи (утилита, JSON, правка 1–2 строк, форматирование) — `enable_thinking:false` (≈8 с, качество на простых задачах не хуже). `max_tokens` включает мышление — ставить с запасом (4096+).
- **Проверенные возможности (батарея 2026-11-09, 10 задач)**: утилита по формуле — верно; поиск и исправление бага — верно; минимальная правка файла (диф ровно в нужных строках) — верно; строгий JSON-вывод — верно; отказ выдумывать неизвестный код (`НЕ_ХВАТАЕТ_ДАННЫХ`) — верно; обнаружение нарушения слоёв FSD и корректное решение — верно; факты из ~8K токенов исходников — верно; React-компонент по ТЗ (CSS-токены, `cn`, tsc) — верно.
